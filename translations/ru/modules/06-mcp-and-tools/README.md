# 06 · MCP и инструменты

## Результат

Подключите Codex к внешним системам, явно определив возможности, доверие и разрешения.

## MCP для актуальных внешних возможностей

MCP-серверы могут предоставлять:

- инструменты для выполнения действий;
- ресурсы с контекстом для чтения;
- повторно используемые запросы.

Примеры: документация, трекеры задач, хостинг исходного кода, базы данных,
дизайн-системы и внутренние знания.

Не вставляйте большие внешние руководства в `AGENTS.md`. Если Codex нужны
актуальные сведения с возможностью поиска, используйте MCP-сервер документации.

## Выбор инструмента

Предпочитайте самый узкий подходящий источник:

1. Локальные файлы — для фактов о кодовой базе.
2. Специализированный коннектор или MCP-сервер — для разрешённых частных данных.
3. Официальную документацию — для поведения продукта и API.
4. Веб-поиск — для актуальной публичной информации.

## Проверка безопасности

Перед подключением MCP-сервера выясните:

- Кто его обслуживает?
- Какие данные он читает?
- Какие действия выполняет?
- Какие учётные данные получает?
- Точно ли обозначены инструменты записи и разрушительных действий?
- Можно ли начать с режима только чтения?
- Считается ли его вывод недоверенным входом?

Выдавайте минимальные права и никогда не добавляйте токены в Git.

## Сочетайте MCP и навыки

MCP предоставляет возможности, а навык — повторяемую процедуру.
Например, навык ревью может запросить метаданные PR через GitHub-коннектор,
затем изучить локальный diff и вернуть замечания в устойчивом формате.

## Добавление и просмотр сервера

CLI управляет настроенными серверами:

```bash
codex mcp list
codex mcp get <name>
codex mcp add <name> --url <streamable-http-url>
codex mcp remove <name>
```

Для локального stdio-сервера укажите исполняемый файл и аргументы после `--`:

```bash
codex mcp add <name> -- <command> <args>
```

Используйте `codex mcp login <name>` и `codex mcp logout <name>`, если сервер
поддерживает соответствующий OAuth. Для bearer-токена задавайте имя переменной
через `--bearer-token-env-var`; сам токен не должен попадать в коммит
конфигурации или историю shell.

Личные серверы настраивайте в `~/.codex/config.toml`.
Одобренную командой конфигурацию репозитория помещайте в `.codex/config.toml`
доверенного проекта, документируя владельца и требуемую аутентификацию.

## Практикум: сервер официальной документации

Практикум меняет личную MCP-конфигурацию, затем удаляет это изменение:

```bash
codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp
codex mcp list
codex mcp get openaiDeveloperDocs
```

Начните новую задачу Codex и попросите:

```text
Используй источник документации разработчиков OpenAI, чтобы проверить,
где обнаруживаются навыки уровня репозитория. Верни официальный источник
и не изменяй файлы.
```

Посмотрите, какой инструмент или ресурс MCP выбран, и убедитесь,
что ответ ссылается на официальный документ. Затем удалите настройку:

```bash
codex mcp remove openaiDeveloperDocs
codex mcp list
```

Если сервер уже управляется вашей организацией, не заменяйте его конфигурацию.
Изучите существующую запись и выполните только запрос на чтение.

Для любого другого сервера повторите проверку безопасности перед установкой
и начните с запроса на чтение.

## Проверка

- Сервер настроен на ожидаемом уровне.
- Учётные данные не записаны в систему контроля версий.
- Вы понимаете транспорт и способ аутентификации.
- Выбор инструмента или ресурса виден в подтверждениях задачи.
- Ответ ссылается на авторитетный документ.
- Сервер можно корректно удалить.
- После удаления Codex сообщает о недоступности источника, а не утверждает, что использовал его.
