# 05 · Инженерные навыки

## Результат

Превратите проверенный инженерный процесс в навык Codex, который легко
найти и который экономно использует контекст.

## Зачем нужны навыки

Навык объединяет инструкции и необязательные справочные материалы, скрипты
и ресурсы. Сначала Codex видит компактные метаданные, при выборе навыка загружает
`SKILL.md`, а вложенные ресурсы читает только при необходимости.
Так подробные инструкции доступны повторно, но не загружаются целиком в каждую задачу.

Сильная модель уже знает общие инженерные практики. Создавайте навык для
измеренного пробела в процессе, конкретных предметных знаний, границы безопасности,
обязательного формата подтверждений или детерминированного ресурса.
Начните без навыка и используйте
[сравнение трёх вариантов](../../resources/engineering-loop-measurement.md),
прежде чем вводить его по умолчанию в команде.

## Структура

```text
skill-name/
├── SKILL.md
├── agents/openai.yaml
├── references/     # optional, read only when relevant
├── scripts/        # optional, deterministic repeated operations
└── assets/         # optional, copied or used in outputs
```

`references/` хранит материалы для чтения по необходимости, `scripts/` —
детерминированные повторные операции, `assets/` — ресурсы для результатов.
В `SKILL.md` обязательны следующие метаданные:

```markdown
---
name: review-code
description: Review code changes for correctness, regressions, security risks, and missing tests. Use for PR, branch, commit, or working-tree reviews.
---

Imperative workflow...
```

Описание служит условием выбора навыка: укажите в нём и возможности, и контекст применения.

## Установка

- Навык репозитория: `.agents/skills/<skill-name>/`.
- Личный навык: `~/.agents/skills/<skill-name>/`.

Вызывайте явно через `$skill-name` или позвольте Codex сопоставить задачу с описанием.

Для оркестратора или процесса, который должен запускаться только по имени,
задайте `policy.allow_implicit_invocation: false` в `agents/openai.yaml`:

```yaml
interface:
  display_name: "Orchestrate Engineering"
  short_description: "Coordinate bounded multi-agent engineering work"
  default_prompt: "Use $orchestrate-engineering for this complex task."
policy:
  allow_implicit_invocation: false
```

Обычные предметные навыки оставляйте доступными для неявного выбора.
Явный вызов нужен для процессов, случайный запуск которых добавит затраты
на координацию или маршрутизацию.

Пример установки в репозиторий:

```bash
mkdir -p .agents/skills
cp -R /path/to/codex-howto/skills/review-code .agents/skills/
```

Затем начните новую задачу:

```text
$review-code Проведи ревью этой ветки относительно main. Начни с существенных
замечаний и перечисли проверки, которые не удалось выполнить.
```

## Выделите повторяемый процесс

Создавайте навык, только когда можете ответить:

1. Какие запросы пользователя должны его запускать?
2. Какая последовательность устойчива в разных проектах?
3. Какие решения остаются специфичными для проекта?
4. Какие подтверждения показывают, что процесс завершён правильно?
5. Какие подробности стоит вынести в необязательные справочные материалы?

Избегайте единого навыка «software-engineer» для всех технологий.
Узкие навыки выбираются надёжнее и проще сопровождаются.

## Практикум A: установить и изучить существующий навык

1. Выберите один навык из репозитория.
2. Прочитайте его `SKILL.md` и справочный материал.
3. Скопируйте его в `.agents/skills/`.
4. Вызовите на небольшой задаче.
5. Запишите, каких знаний о репозитории ему не хватало.
6. Поместите факты репозитория в `AGENTS.md`, а не в переносимый навык.

## Практикум B: создать навык с нуля

Создайте узкий навык `summarize-test-failure` встроенным средством:

```text
$skill-creator Создай навык уровня репозитория с именем summarize-test-failure.

Он должен вызываться при просьбе проанализировать вывод падающих тестов или
тестовые логи CI. Он возвращает упавшую команду, упавшие случаи, краткие
подтверждения первопричины, неопределённость среды и следующий диагностический
шаг. Он не меняет production-код и не возвращает полные логи.
Сделай основной SKILL.md кратким, а шаблон результата вынеси в один
непосредственно связанный справочный файл.
```

Проверьте созданную директорию `.agents/skills/summarize-test-failure/`:

- метаданные `SKILL.md` содержат только `name` и `description`;
- описание включает условия вызова и границы;
- инструкции сформулированы как действия и задают критерии приёмки;
- строки UI в `agents/openai.yaml` заключены в кавычки, а запрос по умолчанию содержит `$summarize-test-failure`;
- справочный файл связан прямой ссылкой из `SKILL.md`.

Попросите `$skill-creator` проверить директорию. Затем проверьте обе стороны выбора:

```text
$summarize-test-failure Проанализируй этот вывод падающих тестов: [вывод без конфиденциальных данных]
```

```text
Реализуй это не связанное с тестами изменение frontend-макета.
```

Первый запрос должен использовать навык, второй — не должен выбирать его неявно.
Если новый или обновлённый навык не виден в `/skills`, перезапустите Codex
и проверьте, где он ищет навыки.

## Практикум C: использовать набор инженерных навыков

Скопируйте [инженерный практикум](../../labs/engineering-playground/README.md)
в три временные директории. Выполните одну задачу без навыка, с полной версией
`engineering-loop` v0.2 и с текущей компактной версией.
Сохраните одинаковыми модель, уровень рассуждений, инструменты, состояние
репозитория и критерии завершения. Добавляйте специалиста лишь в отдельном
сравнении, если его предметные правила существенно влияют на задачу.

Используйте [`engineering-loop`](../../../../skills/engineering-loop/SKILL.md),
если задача должна пройти через исходное состояние, доказательство регрессии,
целевые и широкие проверки, финальное ревью diff и отчёт с подтверждениями.
Он координирует жизненный цикл, а узкие навыки помогают с предметными решениями.

Маршрутизатор [`choose-engineering-flow`](../../../../examples/skills/choose-engineering-flow/SKILL.md)
с явным вызовом сохранён как пример разработки навыка. Не устанавливайте его
по умолчанию: пересекающиеся описания лучше исправить непосредственно,
чем добавлять отдельный шаг маршрутизации.

## Проверка

- Навык выбирается для целевых запросов, но не для соседних задач.
- Новый навык проходит проверку метаданных.
- Основной текст краток и задаёт действия.
- Необязательные подробности доступны по одной прямой ссылке.
- Критерии приёмки дают наблюдаемые подтверждения.
- Нет секретов конкретной среды или опасных настроек по умолчанию.
- Маршрутизатор или оркестратор, требующий вызова пользователем, задаёт соответствующую политику.
- Исходный запуск без навыка показывает, что навык оправдывает расход контекста.
