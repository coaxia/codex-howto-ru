# 00 · Модель работы

## Результат

Выберите интерфейс Codex и механизм инструкций, минимально достаточные для задачи.

## Codex работает как агент

Полезный цикл работы:

```text
понять → исследовать → при необходимости спланировать → изменить → проверить → провести ревью → отчитаться
```

Запрос задаёт текущую работу. Инструкции репозитория и конфигурация определяют
среду, в которой она выполняется. Тесты, линтеры и критерии ревью позволяют
объективно установить, что задача завершена.

## Выберите интерфейс

| Интерфейс | Для чего подходит |
|---|---|
| CLI | Работа с локальным репозиторием преимущественно в терминале и написание скриптов |
| Расширение IDE | Реализация и навигация непосредственно в редакторе |
| Настольное приложение | Планирование, управление задачами, визуальное ревью и работа с подключёнными сервисами |
| Облако / веб | Работа с репозиторием в размещённой среде, параллельное выполнение или перенос задач из локальной среды |

Единого «лучшего» интерфейса нет. Выбирайте с учётом того, где уже находятся
код, контекст, процесс ревью и необходимые разрешения.

## Выберите механизм для повторного использования

| Потребность | Что использовать |
|---|---|
| Одноразовое ограничение | Запрос |
| Правило репозитория | `AGENTS.md` |
| Повторяющийся процесс из нескольких шагов | Навык (Skill) |
| Специализированная роль для делегирования | Пользовательский агент |
| Внешние данные или действие | MCP / коннектор приложения |
| Обязательный шаг в жизненном цикле | Hook |
| Набор компонентов для распространения | Плагин |
| Устойчивый периодический запуск | Автоматизация |

## Упражнение: знакомство с репозиторием

Запустите Codex в небольшом репозитории с разрешением только на чтение:

```text
Составь обзор этого репозитория для нового участника.

Укажи:
1. среду выполнения и менеджер пакетов;
2. основные точки входа;
3. команды сборки, тестирования, линтинга и проверки типов;
4. три наиболее важные архитектурные границы;
5. файлы, подтверждающие каждый вывод.

Не изменяй файлы и не устанавливай зависимости.
```

## Проверка

- Каждая команда подтверждается файлом репозитория.
- Ответ отделяет факты от предположений.
- Ни один файл не изменён.
- Вы понимаете, какой интерфейс лучше выбрать для следующей задачи реализации.
