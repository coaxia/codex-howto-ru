# 02 · CLI и интерфейсы

## Результат

Безопасно запустите Codex, разберитесь в текущем рабочем контексте и выполните
первую обратимую задачу.

## Установка и вход

Используйте [официальную инструкцию быстрого старта](https://developers.openai.com/codex/quickstart).
Предпочитайте официальные установщики или документированные варианты через
менеджер пакетов скопированным сторонним командам.

После установки:

```bash
codex --version
codex
```

Войдите способом, принятым в вашей организации. Аутентификация по API-ключу
и через подписку ChatGPT различаются по оплате и предоставляемому доступу.

## Чек-лист первого сеанса

Прежде чем просить Codex изменить файлы:

1. Проверьте текущую директорию.
2. Проверьте репозиторий и активную ветку.
3. Изучите `git status`.
4. Прочитайте применимые `AGENTS.md`.
5. Найдите ожидаемые команды тестирования и линтинга.
6. Начните с режима разрешений по умолчанию.

## Учитесь на обратимых задачах

Подходящие первые задачи:

- объяснить модуль;
- добавить целевой unit-тест;
- улучшить небольшой раздел документации;
- исправить воспроизведённый дефект с низким риском;
- провести ревью незакоммиченных изменений.

Не начинайте первый сеанс с ротации учётных данных, production-инфраструктуры,
удаления данных или переписывания репозитория без чётких границ.

## Основные интерактивные команды

- `/init` создаёт начальный `AGENTS.md`.
- `/plan` включает режим планирования сложной работы.
- `/permissions` показывает или меняет режим разрешений.
- `/review` выполняет целевое ревью кода.
- `/agent` показывает потоки агентов в поддерживаемых процессах CLI.

Команды меняются. Проверяйте их доступность в [справочнике CLI](https://developers.openai.com/codex/cli).

## Упражнение: одна проверенная правка

```text
Цель: улучшить один вводящий в заблуждение комментарий или абзац документации.
Контекст: перед правкой текста изучи реализацию.
Ограничения: измени только один файл; не меняй поведение программы.
Завершено, когда: текст соответствует реализации и проверки документации
репозитория проходят.
```

Проверьте diff перед приёмкой результата.

## Проверка

- Вы можете объяснить использованный способ аутентификации.
- Вы знаете действующий режим песочницы и порядок согласований.
- Diff содержит только запланированное изменение документации.
- Соответствующая проверка проходит.
