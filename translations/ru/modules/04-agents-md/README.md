# 04 · `AGENTS.md`

## Результат

Закрепите устойчивые знания о репозитории, чтобы не повторять инструкции
в каждом запросе.

## Что помещать в `AGENTS.md`

- структуру репозитория и важные границы;
- команды сборки, тестирования, линтинга, форматирования и проверки типов;
- правила языка и фреймворка, которые не проверяются автоматически;
- обязательные проверки и требования к ревью;
- опасные или запрещённые операции;
- ссылки на подробную архитектурную документацию и правила ревью.

Избегайте биографий, общих советов по программированию, скопированных руководств
по фреймворкам и правил, уже обеспеченных форматтером или линтером.

## Область действия и приоритет

Используйте:

- `~/.codex/AGENTS.md` для личных настроек по умолчанию;
- корневой `AGENTS.md` для общих инструкций репозитория;
- вложенные `AGENTS.md` для правил отдельных поддеревьев.

Инструкции ближе к рабочей директории имеют приоритет. Держите локальные правила
рядом с кодом, на который они распространяются.

## Начните с малого

Выполните `/init`, затем замените предположения проверенными фактами.
Полезный корневой файл может занимать меньше страницы. Ниже сохранён исходный
пример: структура, команды, правила и критерии завершения.

```markdown
# Repository guidance

## Layout
- `apps/web`: browser application
- `services/api`: public API
- `packages/contracts`: shared schemas

## Commands
- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`

## Rules
- Change shared API shapes in `packages/contracts` first.
- Add a migration for persisted schema changes.
- Do not edit generated clients manually.

## Done
- Focused tests and required repository checks pass.
- The final response lists changed files and remaining risks.
```

## Обратная связь

Если Codex повторяет ошибку:

1. Определите, вызвана ли она отсутствием устойчивого контекста.
2. Добавьте минимальное правило в ближайшей применимой директории.
3. По возможности предпочитайте команду проверки описанию словами.
4. Удаляйте устаревшие инструкции при изменении репозитория.

## Упражнение

Адаптируйте [начальный пример](../../../../examples/AGENTS.md) для реального
репозитория. Попросите Codex проверить каждую команду перед сохранением.

## Проверка

- Команды существуют и выполняются в указанной директории.
- Вложенные правила не противоречат корневым по ошибке.
- В файле нет учётных данных или путей, зависящих от конкретного компьютера.
- Другой инженер понимает критерии завершения без дополнительных вопросов.
