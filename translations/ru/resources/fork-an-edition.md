# Создайте собственную редакцию

Поддерживаемая адаптация нужна, если стек, команда, язык или benchmark
требуют инструкций, слишком специфичных для upstream-курса.

Редакция должна назвать аудиторию, закрепить исходную upstream-ревизию,
описать адаптации, собственные проверки и порядок обновления.

## Начните за пять минут

1. [Создайте форк Codex How To](https://github.com/Phelan164/codex-howto/fork).
2. Склонируйте и зарегистрируйте upstream:

   ```bash
   git clone https://github.com/YOUR-ACCOUNT/codex-howto.git
   cd codex-howto
   git remote add upstream https://github.com/Phelan164/codex-howto.git
   git fetch upstream --tags
   ```

3. Создайте ветку редакции от реально проверенного выпуска:

   ```bash
   git switch -c edition/YOUR-EDITION v0.6.0
   cp examples/templates/edition-manifest.md EDITION.md
   ```

4. Заполните `EDITION.md`: аудитория, ревизия, область, адаптации, проверки и синхронизация.
5. Сделайте одно ограниченное изменение и выполните:

   ```bash
   python3 scripts/validate_repo.py
   python3 skills/maintain-codex-wiki/scripts/wiki_lint.py .
   ```

6. Добавьте проверки стека, команды, языка или benchmark из `EDITION.md`.
7. Публикуйте ветку или делайте основной только после успешных описанных проверок.

Внутренние правила, названия инфраструктуры и политики ревью храните
в частном форке. Не публикуйте секреты, данные клиентов, production-логи,
закрытый код или конфиденциальные инструкции.

## Выберите тип редакции

| Тип | Что добавить или заменить | Подтверждения |
|---|---|---|
| Команда | Команды, согласования, правила ревью | Безопасные команды проверки и ответственность |
| Стек | Один фреймворк или маршрут поставки | Выполнимое упражнение и проверки стека |
| Перевод | Учебный маршрут и местный контекст | Проверка терминов и сохранённые официальные источники |
| Benchmark | Воспроизводимые задачи и результаты | Ревизии, приёмка и ограничения |

Сохраняйте upstream-цикл, пока измерения не оправдают изменение.
Узкая редакция с рабочими примерами полезнее каталога непроверенных советов.

## Сопровождение форка

Изучите выпуски до синхронизации:

```bash
git fetch upstream --tags
git log --oneline HEAD..upstream/main
git switch edition/YOUR-EDITION
git merge --no-ff upstream/main
```

Осознанно разрешайте конфликты адаптации, повторите все проверки `EDITION.md`,
обновите ревизию и дату. До успешных проверок не заявляйте совместимость
с новым выпуском.

## Делитесь полезными подтверждениями

- Укажите редакцию в [Show and tell](https://github.com/Phelan164/codex-howto/discussions/categories/show-and-tell).
- Предлагайте общие исправления upstream отдельным PR.
- Отправляйте обезличенные измерения в [issue воспроизведения](https://github.com/Phelan164/codex-howto/issues/23).

Назовите свою связь с редакцией и не просите согласованных звёзд, голосов или форков.
