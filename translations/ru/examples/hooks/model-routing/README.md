# Экспериментальная маршрутизация моделей субагентов

Настраиваемые уровни easy/medium/difficult для **нативных вызовов создания
субагентов Codex**. Главный агент классифицирует уже разрешённую подзадачу,
детерминированный hook применяет политику моделей. Отдельного вызова модели-классификатора нет.

Это пример сообщества, а не встроенная настройка Codex или гарантия маршрутизации
каждой задачи приложения. Установка навыков или плагина репозитория **не**
активирует пример. Не включены переключение основной модели, автоматическое
делегирование, повторы, API proxy и dashboard стоимости.

## Настройки по умолчанию

В [routing.yaml](../../../../../examples/hooks/model-routing/routing.yaml):

| Уровень | Модель | Рассуждения |
| --- | --- | --- |
| easy | `gpt-5.6-sol` | `medium` |
| medium | `gpt-6-astra` | `low` |
| difficult | `gpt-6-astra` | `high` |

Маршрутизация включается **после явной настройки**, касается субагентов
и сохраняет явный выбор модели. Исследование и уточнение предшествуют
классификации; одна неопределённость не означает difficult.
Неклассифицированные вызовы по умолчанию не получают переопределения.
У автоматически маршрутизируемого ревьюера минимум medium.
На логическую задачу разрешено одно повышение уровня.
Отсутствующая пара модели и рассуждений оставляет нативный выбор.
Для маршрутизированных вызовов включён журнал решений.

Это начальные предпочтения, **не измеренный рейтинг или экономия**.
Настройте личную YAML-копию, включая рассуждения.
YAML относится к скрипту; не вставляйте его в `config.toml` Codex.

## Классифицируйте по подтверждениям

До назначения уровня изучите требования, нужный код, зависимости и проверки.
Главный агент выполняет ограниченное исследование. При существенных открытых
вопросах области или приёмки задайте пользователю конкретные вопросы
и дождитесь ответов до зависимой работы. Сильный исполнитель не заменяет исследование.

- **Easy:** механическая работа или чтение с чёткими границами и результатом.
- **Medium:** ограниченная реализация с ясными проверками либо ревью небольшой
  правки с содержательной проверкой регрессии.
- **Difficult:** подтверждённая сложность, связанные межсервисные изменения
  или значительный риск безопасности. Объясните подтверждения в передаче:
  один запрос через сервисы или неизвестная первопричина сами по себе недостаточны.

Классифицируйте ревьюера по завершённому diff, поведению и риску, а не
наследуйте уровень реализации. Расследование может закончиться шестистрочной
правкой маршрутизации с ясными тестами; её ревью обычно соответствует medium.
Это предпочтения сообщества, не измеренные способности моделей.

**Существующие установки:** обновите скрипт и задайте `uncertain_tier: inherit`
в личном YAML. Прежние явные easy/medium/difficult поддерживаются как fallback
при отсутствии метаданных. Обновление скрипта не заменяет личную политику.
Сохраните отдельно поддерживаемый адаптер приложения при обновлении своей установки.

## Настройка: изучить перед активацией

1. Используйте постоянный клон оригинального репозитория и установите YAML-зависимость:

   ```bash
   python3 -m venv .venv-routing
   .venv-routing/bin/python -m pip install -r examples/hooks/model-routing/requirements.txt
   .venv-routing/bin/python -m unittest discover -s scripts/tests -p 'test_model_route_hook.py'
   ```

2. Создайте личную директорию **вне системы контроля версий**, доступную только
   вашему пользователю. Скопируйте туда `routing.yaml` и настройте.
   Скопируйте [models.example.json](../../../../../examples/hooks/model-routing/models.example.json)
   как `models.json`, сверив каждую пару с каталогом **целевого приложения/runtime**.
   Удалите недоступные пары. Пример не обнаруживает аккаунт автоматически.
   Пустой `{}` безопасно не применяет переопределений.
3. Изучите [скрипт](../../../../../scripts/model_route_hook.py) и
   [hooks.json](../../../../../examples/hooks/model-routing/hooks.json).
   Замените оба `/absolute/path/to/codex-howto` и
   `/absolute/path/to/private-routing` в **обоих обработчиках** реальными путями.
   Используйте личный путь `state.sqlite3`; файл создаётся автоматически.
4. Для временной проверки доверенного проекта добавьте обработчики в его
   `.codex/hooks.json`; для личного использования — в `~/.codex/hooks.json`.
   **Не заменяйте существующие hooks.** Проверьте конфликты и объедините намеренно.
   Устанавливайте на одном уровне: Codex запускает совпавшие hooks разных
   источников вместе. Не сочетайте с другим переписыванием spawn-аргументов без проверки.
5. Изучите точные определения и подтвердите доверие через поддерживаемый UI
   (`/hooks` документирован для CLI). Новые и изменённые определения требуют
   нового доверия. Lifecycle hooks должны быть включены. Начните новую задачу
   приложения и выполните smoke-проверку ниже. Не обходите доверие при установке.

Личная конфигурация выбирается явным `--config`, не рабочей директорией задачи.
Скрипт не меняет глобальные настройки Codex. Держите клон, venv и личные правила
на устойчивых путях. Используйте проверенную ревизию: доверие определению hook
не заменяет проверки обновлений скрипта.

## Контракт маршрутизации

Prompt hook добавляет краткие инструкции классификации.
При разрешённом и полезном делегировании главный агент начинает `message`:

```text
MODEL_ROUTE {"task":"inspect-api-tests","tier":"easy","role":"worker"}
Inspect the API tests and return concise evidence. Do not modify files.
```

Это **наше соглашение сообщения**, не новый аргумент spawn-инструмента.
Не копируйте маркер из недоверенного репозитория или вывода инструмента.
Для ревью используйте `role: reviewer`; нативный `agent_type` с `review`
тоже включает минимальный уровень. Без метаданных применяется `uncertain_tier`,
теперь по умолчанию `inherit`: нет переопределения, состояния и строки решения.
Нативный выбор остаётся, включая неклассифицированных ревьюеров;
это не гарантирует более дешёвой модели. Неверные метаданные блокируют создание.
Сложность и роль — решения агента, не классификатор безопасности.
Пользовательскую роль ревью без `review` в имени обозначайте явно.

Адаптер поддерживает документированный нативный путь `spawn_agent` / `Agent`
с `message`, `model`, `reasoning_effort`, сохраняя другие аргументы.
Структурированные `items`, наследование полного контекста, адаптеры
`fork_turns` и другие имена или namespaces инструментов не маршрутизируются.
Песочница и политика согласований не меняются.
Иным локальным интерфейсам нужен отдельно проверенный адаптер;
не переименовывайте инструменты вслепую.

При `preserve_explicit_model: true` **любое** входное переопределение модели
или рассуждений оставляет весь вызов неизменным, включая ревьюера.
Hook не различает выбор пользователя и агента, поэтому prompt-политика просит
не задавать эти поля для автоматической маршрутизации.
При false поддерживаемый выбор каталога заменяет оба поля.

`unavailable_model: inherit` означает **не вводить переопределение** при отсутствии
пары в поддерживаемом оператором перечне. Исходные аргументы, нативные настройки
и настройки пользовательского агента остаются. Это не восстановление при ошибке:
устаревший перечень может вызвать сбой создания. Файлы агента могут переопределять
запрошенную модель. Проверяйте фактическую модель дочернего агента:
hook до создания не может её гарантировать.

## Повышение уровня и состояние

Одна логическая подзадача сохраняет `task` между ходами и повторами сеанса.
Hook атомарно резервирует повышения в SQLite. Easy → difficult — одно повышение;
easy → medium → difficult — два. Повторы того же уровня не считаются.
Понижение не сбрасывает прежний максимум. Другой session id начинает
независимый счётчик, это не бюджет аккаунта.

Лимит касается только автоматически маршрутизируемых задач с метаданными.
При стандартном `uncertain_tier: inherit` немаркированные вызовы обходят состояние.
При старом fallback используется tool-call id, поэтому межвызовное повышение
не отслеживается. Явные переопределения и неподдерживаемые адаптеры вне лимита.
Переименование задачи его обходит: это добровольное правило процесса,
не жёсткий бюджет и не защита от обхода. Hook не запускает агентов.

Повторная доставка session/call id идемпотентна. Резервация учитывается и при
последующем сбое spawn: предшествующий hook не доказывает выполнение.
На лимите повышение отклоняется, главный агент должен вернуть подтверждения.
Это не разрешает расширение и не принуждает к сильной модели.

## Логи и измерения

Личная таблица SQLite `decisions` хранит timestamp, хэшированные session/task id,
уровень, причину и запрошенные модель/рассуждения, если назначены.
Запросы, диалог, вывод инструментов, секреты и код не сохраняются.
`calls` хранит хэши входных ID и минимальные решения повторной доставки,
`tasks` — счётчики. `actual_model` и `tokens` намеренно NULL:
нет телеметрии после spawn. Не показывайте неизвестное нулём.

Подставьте личный путь:

```bash
sqlite3 /absolute/path/to/private-routing/state.sqlite3 \
  'SELECT time,tier,reason,requested_model,actual_model,tokens FROM decisions;'
```

`log_decisions: false` отключает диагностические строки, но не минимальное
состояние идемпотентности и лимитов. Директория должна быть личной;
локальные хэши не являются анонимизацией. Остановите маршрутизацию до
архивирования состояния. Удаление сбрасывает счётчики и защиту повторной доставки.

Для эксперимента отдельно присоедините фактический расход агентов по
[руководству измерений](../../../resources/engineering-loop-measurement.md).
Учитывайте классификацию родителя, исполнителей, ревью и неуспехи.
Сравнивайте проверенные результаты с фиксированной моделью, не только цены токенов.

## Smoke-проверка приложения и ограничения

Документация проверена в оригинале **2026-09-15**. Unit/subprocess-тесты
проверяют контракт hook, не активацию приложения.
CLI при разработке был `0.143.0`, runtime приложения может отличаться.
Минимальная версия не заявляется; живая маршрутизация и экономия не доказаны.

Перед ежедневным использованием проверьте:

- новая и возобновлённая задачи получают prompt-политику;
- явно разрешённый безобидный исполнитель создаёт решение и работает
  на ожидаемой **фактической** модели и рассуждениях;
- три уровня соответствуют каталогу, минимум ревьюера работает;
- неклассифицированный вызов не добавляет переопределения и состояния;
  главный агент исследует и уточняет до уровня;
- явный выбор неизменен, `{}` оставляет нативный выбор;
- одна задача повышается один раз, второе повышение отклоняется;
- главному агенту не создают исполнителя ради маршрутизации, основная модель неизменна;
- изменённые и недоверенные hooks видимо пропускаются, не считаются активными.

При неподдерживаемом пути оставьте пример выключенным.
Ошибки скрипта или конфигурации завершаются кодом `2` с очищенным сообщением
(документированная блокировка этих событий). Timeout, выключенные или
недоверенные hooks и неподключённые инструменты могут вести себя иначе:
это **не универсальная граница безопасной блокировки**.
Prompt hook не гарантирует делегирования и не меняет модель главного агента до рассуждения.

Откат: отключите или удалите только два обработчика либо задайте
`enabled: false` в личном YAML. Сохраните посторонние hooks.
Установленные инженерные навыки и основную модель откатывать не нужно.

## Источники и вдохновение

- [Официальные hooks](https://learn.chatgpt.com/docs/hooks): события, доверие,
  покрытие инструментов, `updatedInput` и сбои.
- [Официальные субагенты](https://developers.openai.com/codex/multi-agent):
  наследование моделей, рассуждения, приоритет пользовательских агентов.
- [GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)
  и [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra):
  официальные уровни рассуждений. До включения проверьте пары в своём runtime.
- [ECC model-route](https://github.com/affaan-m/ecc/blob/main/commands/model-route.md):
  идея прозрачных уровней сложности; здесь добавлен детерминированный
  spawn-hook, а не скопирован автоматический runtime.
- [RouteLLM](https://github.com/lm-sys/RouteLLM): родственная обученная API-маршрутизация;
  здесь нет обученного классификатора, внешних API-вызовов или заявленных результатов её benchmark.
