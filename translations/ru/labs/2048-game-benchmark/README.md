# Benchmark 2048 без зависимостей

Это задача реализации среднего объёма для
[протокола измерения инженерного цикла](../../resources/engineering-loop-measurement.md).
Она намеренно больше backend-упражнения: нужны переходы состояния,
детерминированная случайность, ввод в браузере, доступность, адаптивный интерфейс,
автоматические проверки, ревью и передача подтверждений.

Работайте только во временной копии [оригинального примера](../../../../labs/2048-game-benchmark/README.md).
Изначально нет реализации `game/`, поэтому предоставленные тесты падают.
Команды ниже выполняются из корня оригинального репозитория:

```bash
cd labs/2048-game-benchmark
benchmark_root="$(mktemp -d)"
cp -R AGENTS.md README.md TASK.md test .gitignore "$benchmark_root/"
cd "$benchmark_root"
git init
git add .
git commit -m "baseline 2048 benchmark"
```

Создайте три свежие копии одного коммита и следуйте протоколу.
Не копируйте `evaluator.mjs` в кандидат. Применяйте его только после завершения всех вариантов:

```bash
node /path/to/codex-howto/labs/2048-game-benchmark/evaluator.mjs \
  /path/to/candidate \
  /path/to/codex-howto/labs/2048-game-benchmark
```

Первый опубликованный результат:
[измерение GPT-5.6-sol для игры 2048](../../../../examples/measurements/gpt-5.6-sol-2048-game-2026-07-31.md).

## Обязательные файлы

```text
game/
├── app.mjs
├── engine.mjs
├── index.html
└── styles.css
```

## Контракт движка

`game/engine.mjs` экспортирует:

- `SIZE`, равный `4`;
- `createGame({ random } = {})`;
- `move(state, direction, { random } = {})`;
- `spawnTile(board, random)`;
- `canMove(board)`.

Состояние содержит `board` из 16 значений, числовой `score`
и `status`: `playing`, `won` или `lost`.

- Новая игра содержит ровно две созданные плитки.
- Создание выбирает пустую ячейку через переданный генератор случайности
  и добавляет `2` в 90% случаев либо `4` в 10%.
- `move` принимает `left`, `right`, `up`, `down`, не меняя входное состояние.
- Равные соседние плитки объединяются один раз за ход, результат прибавляется к счёту.
- Изменивший доску ход создаёт одну плитку; ход без изменения не создаёт.
- Достижение 2048 означает победу; отсутствие допустимых ходов — поражение.
- Завершённое состояние отклоняет новые ходы.

## Контракт браузера

- Загрузить `app.mjs` из `index.html` как модуль.
- Вывести игру в `#board`, счёт в `#score`, объявления в `#status`.
- Предоставить нативную кнопку `#restart`.
- Поддержать стрелки и WASD, предотвращать прокрутку для обработанных клавиш
  и игнорировать остальные.
- Дать доске понятную семантику, изменения статуса объявлять через live region.
- Использовать адаптивный макет без внешних шрифтов, изображений и библиотек.

## Приёмка

- Предоставленные тесты побайтово неизменны, `node --test` проходит.
- Оценщик после завершения проходит.
- Финальный diff содержит только реализацию и запрошенный отчёт.
- Отчёт разделяет автоматические подтверждения, выполненные браузерные действия,
  непроверенное поведение и остаточные риски.

Оценщик проверяет детерминированные граничные случаи движка и статический
контракт браузера. Он не заменяет интерактивную, визуальную проверку
или тестирование вспомогательными технологиями.
