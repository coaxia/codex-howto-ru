# Codex Living Wiki

Это справочный перевод [оригинальной wiki](../../../knowledge/README.md).
Изменения знаний, реестр источников и операции сопровождения выполняются
в исходном `knowledge/`; перевод не является вторым реестром.

Директория оригинала — слой знаний сопровождающих с предварительным ревью.
Она обобщает подтверждения о процессах Codex в короткие связанные
Markdown-страницы, не заменяя учебный курс, проверенный людьми.

## Границы

- Официальная документация OpenAI авторитетна для поведения Codex.
- `modules/` и `resources/` — опубликованный учебный комплект.
- `skills/` содержит процедуры, а не копию wiki.
- `AGENTS.md` задаёт правила каждой задачи репозитория.
- `knowledge/` фиксирует понимание, подтверждения, неопределённость,
  решения и эксперименты для возможного последующего переноса.

Внешние тексты находятся в игнорируемом `.wiki-cache/`, если лицензия
и правила репозитория не разрешают распространение.
Исходный [sources.json](../../../knowledge/sources.json) хранит устойчивые ID и происхождение.

## Операции

Установите или явно вызовите
[`maintain-codex-wiki`](../../../skills/maintain-codex-wiki/SKILL.md):

```text
$maintain-codex-wiki Query: что репозиторий знает о навыках с учётом модели?
Ссылайся на страницы wiki и не меняй файлы.
```

```text
$maintain-codex-wiki Ingest: включи это обновление официальной документации
Codex. Подготовь проверяемый diff wiki, выполни lint, пока не переноси в модуль.
```

Явно фиксируйте устойчивые подтверждения репозитория:

```text
$maintain-codex-wiki Capture: сохрани повторно применимый урок объединённого
изменения. Используй подтверждения репозитория, допускай отсутствие существенного
изменения и пока не выполняй перенос.
```

Архивируйте ответ со ссылками, только если он заслуживает сохранения:

```text
$maintain-codex-wiki Archive: сохрани этот ответ как экспериментальные знания.
Сохрани ID источников, свяжи страницы и выполни wiki lint.
```

Из корня репозитория:

```bash
python3 skills/maintain-codex-wiki/scripts/wiki_lint.py .
```

## Модель ревью

1. Зарегистрируйте или используйте источник с устойчивой ревизией, если доступна.
2. Обновите минимальный набор затронутых страниц.
3. Выполните детерминированные проверки и изучите смысловые подтверждения.
4. Проведите ревью diff через PR.
5. Переносите устойчивые выводы в модули, навыки, правила или проверки
   только по явному запросу.

Плановое сопровождение может сообщать расхождения или готовить draft PR.
Оно не должно писать прямо в защищённую ветку или молча превращать
практику сообщества в официальную рекомендацию.
